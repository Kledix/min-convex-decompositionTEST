Minimum Convex Decomposition

How do we cut a simple polygon into the fewest possible convex pieces?

Based on the algorithm by J. Mark Keil & Jack Snoeyink (2002)

Project by Deliallisi Klejdi, Aknaf Imran

Try the demo ↓

Abstract

Many algorithms (collision detection, path planning, rendering) work far better on convex shapes than on arbitrary ones. We study the problem of splitting a simple polygon into the fewest convex pieces using non-crossing diagonals. We start from the brute-force solution, whose cost explodes with the polygon size, then follow the dynamic-programming line of work of Greene (1983), Keil (1985) and Keil & Snoeyink (2002), explaining what each step fixed. An interactive demo lets you build a polygon and watch a fast heuristic decompose it, compared with a provable lower bound.

1. Introduction

A simple polygon is a closed chain of \(n\) straight edges that never crosses itself. It is convex if the segment joining any two of its points stays inside. A vertex is reflex when its interior angle exceeds 180°; a polygon is convex exactly when it has no reflex vertex. We write \(r\) for their number.

A diagonal joins two vertices through the interior. A triangulation adds diagonals until only triangles remain, and always uses exactly \(n-2\) triangles. A convex decomposition only asks for convex pieces, so it can use far fewer.

Lower bound. A diagonal can fix at most two reflex vertices (one at each end), so any decomposition needs at least \(\lceil r/2\rceil+1\) pieces. For the L-shape, \(r=1\) gives 2, so the result above is optimal.

Why only simple polygons?

This project is restricted to simple polygons, because for a polygon whose edges cross each other the basic notions we rely on are no longer well defined:

  • Interior: the inside of the polygon is ambiguous. Different conventions (even-odd rule, winding number) can give different regions, so "a diagonal lying inside" has no single meaning.
  • Diagonals: a segment may cross an edge or pass through a crossing point that is not a vertex, so it is unclear which segments are valid diagonals.
  • Visibility: two points "seeing each other" relies on the segment staying inside the polygon, which again depends on the chosen interior.
  • Structure: a diagonal no longer splits the polygon into exactly two sub-polygons, and results such as "a triangulation has \(n-2\) triangles" no longer hold. The dynamic programming below relies on this splitting.

Simple polygons give a clean, unambiguous setting, which is why the literature on this problem uses them.

2. The Problem: The Robot Vacuum Analogy

Imagine a robot vacuum in an L-shaped flat. To plan its route, it would like every zone to have no hidden corners. A region where any two points can see each other (the segment between them stays inside) is called convex.

Formally: given a simple polygon, partition it into the minimum number of convex sub-polygons using non-crossing diagonals (Steiner points are not allowed in this version of the problem). A Steiner point is an extra vertex that is not a vertex of the original polygon, for example a point on an edge where a cut ends. Here every cut must join two existing vertices.

Note on Steiner points: If we allow segments to end at arbitrary new points (Steiner points) rather than just existing vertices, the problem was solved in \(O(n + r^3)\) time by Chazelle and Dobkin (1985). This project focuses strictly on decompositions without Steiner points, where cuts must join existing vertices.

3. A Naive Approach (and Why It Fails)

Brute force: try every set of diagonals

1. D ← all valid diagonals of P                 # O(n²) candidates, O(n) test each
2. for every subset S of D with no two diagonals crossing:
3.     pieces ← cut P along S
4.     if every piece is convex: keep S if |S| + 1 is the smallest so far
5. return the best S

It works: it examines every possible answer, so the result is exactly optimal. It does not scale: a polygon has up to \(D=n(n-3)/2\) diagonals, hence up to \(2^{D}\) subsets. Keeping only non-crossing subsets helps but the count stays exponential (about \(5.83^n\) for polygons whose vertices see each other).

Where does 5.83 come from?

Count the sets of non-crossing diagonals of a convex \(n\)-gon (the most favourable case for diagonals): 1, 3, 11, 45, 197, 903 for \(n=3,\dots,8\) (the little Schröder numbers). The ratio between consecutive terms tends to \(3+2\sqrt2\approx5.83\), so the count grows like \(5.83^n\). For comparison, complete triangulations alone only grow like \(4^n\). A simple polygon has fewer valid diagonals, so this is an upper bound.

Greedy: triangulate, then merge

1. T ← any triangulation of P                  # e.g. ear clipping
2. for each diagonal d of T:
3.     if removing d keeps the merged piece convex: remove d
4. return the remaining pieces

This is the Hertel–Mehlhorn heuristic used in the demo. It is fast (linear after the triangulation) and always valid, but not optimal: the order of the merges can lock in a bad choice.

Why it is within a factor 4 of the optimum

Every diagonal left at the end is essential: removing it would create a reflex angle at one of its endpoints. A reflex vertex can have at most two essential diagonals incident to it (a third would be removable). So at most \(2r\) diagonals remain, giving at most \(2r+1\) pieces. Since \(\mathrm{OPT}\ge\lceil r/2\rceil+1\), the ratio is below 4.

So: brute force is exact but exponential, greedy is fast but only approximate. The dynamic-programming algorithms below are exact and polynomial.

4. Algorithmic Evolution

All three algorithms below are exact dynamic programs over sub-polygons cut off by a diagonal. They differ in how many subproblems they create and how much each one costs. Here \(n\) is the number of vertices and \(r\) the number of reflex vertices.

1983

Greene — \(O(n^2 r^2)\)

Idea. For a diagonal \(d\), some convex piece of the optimal solution is incident to \(d\). Greene builds this piece vertex by vertex, removes it, and solves what remains.

Limit. Removing a piece with \(k\) sides can leave up to \(k-1\) separate sub-polygons: one problem becomes many, and every combination of piece shapes must be examined.

Proof sketch of the bound

A subproblem is a diagonal with a reflex endpoint, so there are \(O(rn)\) of them. Choosing the convex piece next to a diagonal means exploring \(O(rn)\) candidate extensions. Multiplying gives \(O(rn)\cdot O(rn)=O(n^2r^2)\).

1985

Keil — \(O(nr^2\log r)\)

What is new. Instead of removing a whole convex piece, Keil removes a single triangle, leaving at most two subproblems. He also shows that among candidate diagonals, only the narrowest pairs can appear in an optimal solution, allowing the rest to be discarded.

Gain. The fan-out of Greene disappears. The number of subproblems stays \(O(rn)\), but the work per subproblem drops to \(O(r\log r)\).

Proof sketch of the bound

Replacing the \(O(rn)\) work per subproblem by \(O(r\log r)\) gives \(O(rn)\cdot O(r\log r)=O(nr^2\log r)\). Correctness rests on the definition of narrowest pairs: the convex region of such a pair, near the diagonal, does not contain the convex region of any other minimum decomposition, so discarding the other candidates loses nothing.

2002

Keil & Snoeyink — \(O(n + r^2\min(r^2,n))\)

What is new. Keil & Snoeyink introduce three major improvements: a canonical triangulation to resolve merging ambiguities, replacing the search structure with stacks to drop the \(\log r\) factor, and using ray shooting to restrict the problem to biased convex decompositions.

Gain. Ray shooting first identifies a reduced set of at most \(\min(n,r^2)\) relevant convex vertices; the \(r\) reflex vertices are retained as well. For \(r\ge1\), the reduced polygon therefore has \(O(\min(n,r^2))\) vertices. Theorem 3's amortized stack analysis on this reduced input gives \(O(r^2\min(r^2,n))\) DP time. When \(r\) is small relative to \(n\), this is dramatically faster, and the full bound including preprocessing never exceeds \(O(n^3)\).

Proof sketch of the bound

The DP is first shown to take \(O(n r^2)\) time globally because it makes at most \(O(n r^2)\) subroutine calls, and the total internal work is bounded by \(O(n r^2)\) stack pops. Then, a geometric reduction restricts the number of relevant convex vertices to at most \(\min(n, r^2)\). Running the DP on this geometrically reduced problem substitutes \(n\) with \(\min(n, r^2)\), giving \(O(r^2\min(r^2,n))\), plus \(O(n)\) for the initial preprocessing. Since \(r \le n\), the total is at most \(O(n^3)\).

How the bounds are derived

For Greene and Keil, a simple reading works: running time = number of states × work per state, where a state is a diagonal, i.e. a sub-polygon to solve. The proof for Keil & Snoeyink is different: it is an amortized argument, explained in the last item.

  • Greene. A useful diagonal has at least one reflex endpoint (\(r\) choices) and any other endpoint (\(n\) choices): \(O(rn)\) states. Building the convex piece incident to a diagonal costs about \(O(rn)\) again. Total: \(O(rn)\cdot O(rn)=O(n^2r^2)\).
  • Keil. Same \(O(rn)\) states, but the narrowest pairs discard most candidates, so each state costs only \(O(r\log r)\). Total: \(O(rn)\cdot O(r\log r)=O(nr^2\log r)\).
  • Keil & Snoeyink. To prove the complexity, the 2002 paper splits the analysis in two. First, Theorem 3 proves an \(O(n r^2)\) bound for the DP without using the "states × work" logic. Instead, it demonstrates globally that the algorithm makes at most \(O(n r^2)\) calls to its subroutines, and the computation time inside them is bounded by the number of elements popped from the stacks. Since elements are pushed at most once, the total number of pops cannot exceed \(O(n r^2)\). Second, Section 4 introduces a ray-shooting geometric reduction that restricts the valid convex endpoints to at most \(\min(n, r^2)\). Running the DP on this reduced set substitutes \(n\) with \(\min(n, r^2)\), improving the DP runtime to \(O(r^2\min(r^2,n))\).

Sanity check. If \(r\) grows like \(n\), Greene gives \(n^4\) while Keil & Snoeyink give \(n^2\cdot n=n^3\). If \(r\) is a constant, Keil & Snoeyink reduce to \(O(n)\).

What comes from the paper. The 2002 article states the total bounds, the \(\min(n,r^2)\) relevant endpoints and the amortized argument for its own algorithm (Theorem 3). The split into states and work per state for Greene and Keil is a structural reading of their totals, not something the paper spells out.

Why the 2002 paper is a real breakthrough

  • It changes the structure of the recurrence. Earlier algorithms only tuned the cost of each step; Keil & Snoeyink removed the root cause, the fan-out of one problem into many.
  • It improves the worst case. From \(O(n^4)\) (Greene) to \(O(n^3)\), and it removes the \(\log r\) factor of Keil, since \(\min(r^2,n)\le n\).
  • It adapts to the input. The cost depends on \(r\), not only on \(n\): for a convex polygon (\(r=0\)) or any constant \(r\), the running time is linear, \(O(n)\).

What does "one triangle per step" mean?

Greene removes a whole convex piece with \(k\) sides, and every side except the base opens its own independent sub-polygon: the problem explodes into many at once. Keil (1985) introduced the idea of removing a single triangle to leave at most two sub-polygons. Keil & Snoeyink push this further by fixing a canonical triangulation (a triangulation chosen by a fixed rule) so that, for each sub-polygon, the triangle sitting on its base diagonal is fully predictable. The recurrence is then unambiguous.

Concretely, for a sub-polygon bounded by the diagonal \((v_i,v_j)\), the triangle \(\Delta(v_i,v_j,v_k)\) cuts it into \(P_{i,k}\) and \(P_{k,j}\), whose answers were computed earlier.

Why only diagonals with a reflex endpoint matter

Cutting is only useful to remove a reflex angle. A diagonal whose two endpoints are both convex can always be erased: the two pieces it separates merge without creating any reflex angle, because at each endpoint the merged angle equals the original interior angle, which is below 180°. A minimum decomposition therefore never needs such a diagonal. This reduces the candidates from \(O(n^2)\) to \(O(rn)\).

Proof sketch

Let \(d\) join two convex vertices \(u,w\) of the polygon. The angles of the two adjacent pieces at \(u\) add up to the polygon's interior angle at \(u\), which is below 180°; the same holds at \(w\). All other vertices keep their angles. So the union of the two pieces is convex, and removing \(d\) gives a valid decomposition with one piece fewer.

This is a necessary ingredient, but it was already used by Greene and Keil. The new ideas of 2002 are the biased convex decompositions, which shrink the set of useful endpoints, and the canonical triangulation, which limits each step to two subproblems.

From \(n\) to \(\min(n, r^2)\) relevant endpoints

Count the candidate states. A diagonal needs at least one reflex endpoint, and the other endpoint can be any vertex: \(r\times n\) pairs, hence \(O(rn)\) states for Greene and Keil. Keil & Snoeyink restrict the problem to biased convex decompositions. They prove that we only need to consider diagonals ending at specific convex vertices (found by extending lines from reflex vertices). By using a ray-shooting preprocessing step, they eliminate useless convex vertices, reducing the number of valid endpoints to at most \(\min(n, r^2)\). This geometric reduction, combined with the DP, yields the final bound.

Why a canonical triangulation?

If the geometric reduction above bounds the number of relevant endpoints, the canonical triangulation bounds the fan-out (the number of new subproblems created). A canonical triangulation is built with a fixed rule (e.g., connecting the lowest-indexed reflex vertex to others in the piece), so every sub-polygon has exactly one predictable triangle on its base diagonal. The recurrence is then unambiguous, and removing this single triangle creates at most two smaller subproblems instead of splitting into many parts like Greene did.

Why reflex vertices are so important

  • Convexity: a polygon is convex exactly when it has no reflex vertex, so reflex vertices are the only obstacle.
  • Cuts: a cut matters only if it touches a reflex vertex (shown above).
  • Lower bound: each diagonal fixes at most two of them, so at least \(\lceil r/2\rceil+1\) pieces are needed.
  • Complexity: \(r\) measures how hard the polygon really is, which is why it appears in every bound.

Why \(r\) is an interesting parameter

Polygons such as floor plans or building footprints often have many vertices but few notches: a large \(n\) with a small \(r\). The cost \(O(n+r^2\min(r^2,n))\) then stays close to linear. This is not universal: a finely sampled curved boundary can have \(r\) proportional to \(n\), and the bound degrades to \(O(n^3)\).

6. Under the Hood: Mathematics

Trying every set of diagonals takes exponential time. Dynamic programming avoids this thanks to optimal substructure: an optimal decomposition of a polygon contains optimal decompositions of its sub-polygons.

The Keil & Snoeyink algorithm, step by step

A simplified outline of the algorithm, to see how the pieces fit together:

  1. Step 1: Preprocess. Identify the \(r\) reflex vertices. Use ray shooting to find the limited set of convex vertices that can actually form valid optimal diagonals (RE-diagonals and DE-diagonals).
  2. Step 2: List the candidate diagonals. Compute which pairs of these relevant vertices see each other inside the polygon. Ray shooting reduces the convex endpoints to at most \(\min(n,r^2)\), in addition to the \(r\) reflex vertices.
  3. Step 3: Define the subproblems. Each candidate diagonal cuts off a sub-polygon. Its answer records the minimum number of convex pieces and a stack of narrowest-pair candidates associated with optimal solutions.
  4. Step 4: Handle the base case. The polygon's own edges are the simplest subproblems: they need no cut and serve as the starting point of the table.
  5. Step 5: Apply the recurrence. For each sub-polygon, try the possible canonical triangles next to its diagonal. Each choice leaves at most two smaller sub-polygons. The stack operations maintain and compare the narrowest-pair candidates in angular order, discarding entries that cannot contribute to a valid minimum merge.
  6. Step 6: Fill the table bottom-up. Process the sub-polygons from the smallest to the largest, so every answer is computed once and reused.
  7. Step 7: Reconstruct the solution. Starting from the whole polygon, follow the stored best choices back down to form the minimum convex decomposition.

Subproblems

Let \(P=(p_0,\dots,p_{n-1})\). For a diagonal \(d_{ik}\), let \(P_{ik}\) be the sub-polygon it cuts off, and \(w_{ik}\) the minimum number of convex pieces for it.

Recurrence (sketch)

Fix the canonical triangle \(\Delta(p_i,p_j,p_k)\) incident to the diagonal \(d_{ik}\). It leaves at most two smaller subproblems, \(P_{ij}\) and \(P_{jk}\). Taking the best \(j\) (with \(i < j < k\)) gives the additive recurrence: $$w_{ik}=\min_{j} \begin{cases} w_{ij} + w_{jk} + 2 & \text{if } d_{ij} \text{ must be included} \\ w_{ij} + w_{jk} + 1 & \text{otherwise} \end{cases}$$ The algorithm dynamically determines whether the penalty is +1 or +2 depending on whether merging the triangle with the adjacent pieces creates a reflex angle. Since every valid choice of \(j\) is tested, the minimum over all of them is the optimum.

The merge problem

Adding \(\mathrm{OPT}(i,k)+\mathrm{OPT}(k,j)+1\) for the triangle overcounts if the triangle and adjacent pieces can fuse into one convex piece. Whether they can depends on the angles at the shared vertices. To handle this efficiently, the DP stores the optimal count together with a stack of narrowest-pair candidates, maintained in angular order. The recurrence pops candidates that cannot give a valid convex merge instead of enumerating every geometric combination.

A first, naive DP bound

  • States: a subproblem is a diagonal, and there are at most \(\binom{n}{2}=O(n^2)\) of them.
  • Transition: choosing \(v_k\) costs \(O(n)\) candidates per state.
  • Total: \(O(n^2)\times O(n)=O(n^3)\).

The refinement. Only diagonals with at least one reflex endpoint matter (proof in Section 4). This cuts the candidates from \(O(n^2)\) to \(O(rn)\); the biased convex decompositions of Keil & Snoeyink then reduce the useful other endpoints to at most \(\min(n,r^2)\), which leads to the final bound \(O(n + r^2\min(r^2,n))\).

7. Beyond Simple Polygons: Polygons with Holes

Everything above assumes a polygon without holes. If the polygon may contain holes (think of a room with pillars), the problem changes nature: minimum convex decomposition becomes NP-hard (Lingas, 1982). No polynomial-time exact algorithm is expected unless P = NP.

The intuition: in a simple polygon, each diagonal splits the problem into two independent parts, which is exactly what dynamic programming needs. With holes, a diagonal may not disconnect the polygon, so the subproblems are no longer independent. In practice one uses approximations such as the Hertel–Mehlhorn heuristic from Section 3, which still applies. This lies beyond the scope of this project.

8. Real-World Applications

🎮

Physics engines

Collision tests between convex shapes are cheap and robust (GJK, SAT). Concave bodies are split into convex parts first.

🤖

Robotics

Free space split into convex regions: any two points in a region are connected by a straight, safe path.

👁️

Shape analysis

Convex parts act as simple building blocks for recognising and comparing shapes.

9. Conclusion

Minimum convex decomposition is a good example of how a few basic notions of computational geometry (convexity, reflex vertices, diagonals, triangulations) combine into a problem that is easy to state and surprisingly hard to solve well. A naive search is exact but unusable beyond a handful of vertices, a greedy heuristic is fast but only approximate, and the dynamic-programming algorithms of Greene, Keil and Keil & Snoeyink bring the exact answer into polynomial time, step after step. The problem remains relevant today, since convex pieces are the standard building blocks of physics engines, robot navigation and shape analysis. Yet finding the true optimum is not easy: the best exact algorithm is intricate, and as soon as the polygon has holes the problem becomes NP-hard, so in practice simple heuristics are often what actually gets used.

Walkthrough · Part 1

Foundations: what exactly are we cutting?

Definitions

(a) Simple polygon. A polygon \(P\) with \(n\) vertices: a closed chain of straight edges that never crosses itself.

(b) Convex region. A region where any two of its points see each other: the segment between them stays inside.

(c) Internal diagonal. A segment joining two vertices of \(P\) that lies fully inside \(P\).

Goal

Cut the inside of \(P\) with internal diagonals that do not cross, so that every piece is convex, using the minimum number of diagonals.

Intuition

Reflex vertices are the obstacle. A vertex is reflex when its interior angle is larger than \(180^\circ\); we write \(r\) for their number. A polygon is convex exactly when it has no reflex vertex, so a simple polygon is non-convex only because of its reflex vertices.

Our goal: use diagonals to break every reflex angle into convex angles (≤ 180°).

Claim 1

Every diagonal used in a minimum convex decomposition touches at least one reflex vertex.

Proof

  1. Every reflex vertex must be adjacent to at least one diagonal. If it was not the case, a reflex vertex would remain alone, making one of the regions non-convex.
  2. A diagonal between two convex vertices cannot exist. Indeed, suppose such a diagonal exists: we can just delete it, no reflex vertex appears and the merged piece is still convex, so it was not a minimal convex decomposition.

So every diagonal of a minimum decomposition touches at least one reflex vertex.

How many diagonals do we need at least? (lower bound)

  • Every reflex vertex needs at least one diagonal.
  • A diagonal has two endpoints, so it can serve at most 2 reflex vertices.
  • Hence we need at least \(\lceil r/2\rceil\) diagonals.
  • So we need at least \(\lceil r/2\rceil+1\) convex pieces.

…but the lower bound is not always reached

For example: Does a diagonal always remove a reflex angle? No. A diagonal splits the angle in two parts, and the vertex is only fixed when both parts are \(\le180^\circ\). If the reflex angle is close to \(360^\circ\) and the diagonal cuts it very unevenly, one part is still reflex.

So \(\lceil r/2\rceil+1\) is only a lower bound.

Here the lower bound for \(r=1\) gives 2 regions while as we can see the minimum convex decomposition need 3 regions.

Conventions used from now on

We will use this same polygon (\(n=13\), \(r=4\)) for all the examples that follow.

  • The diagonal joining \(p_i\) and \(p_j\) (with \(i<j\)) is written \(d_{ij}\).
  • \(d_{ij}\) is valid only if it lies fully inside \(P\). We write visible(i,j) for this.
  • “Reflex” and “convex” always refer to a vertex’s status in the original polygon \(P\).

Dynamic programming: what is a sub-problem?

  • Sub-polygon \(P_{ik}\) = the part of \(P\) cut off by the diagonal \(d_{ik}\), with vertices \(p_i, p_{i+1}, \dots, p_k\).
  • Size of \(P_{ik}\) = number of vertices of \(P_{ik}\). Here \(P_{04}\) has size 5.
  • Weight \(w_{ik}\) = minimum number of diagonals needed to cut \(P_{ik}\) into convex pieces. The base \(d_{ik}\) is not counted. Here \(w_{04}=0\): \(P_{04}\) is already convex.
  • By Claim 1, \(p_i\) or \(p_k\) is reflex (here both are).
  • The whole polygon is \(P_{0,12}\) (closed by the edge \(p_{12}p_0\)). We want \(w_{0,12}\); the number of pieces is \(w_{0,12}+1\).

Intuition of the DP

  • To compute \(w_{ik}\), we use the weights \(w_{xy}\) of the smaller sub-polygons \(P_{xy}\) inside \(P_{ik}\).
  • We therefore go from small sizes to large sizes. The last sub-polygon, \(P_{0,12}=P\), gives the answer.
  • How to combine the smaller sub-polygons is exactly what differs between Greene, Keil and Keil & Snoeyink (next parts).

How to solve a sub-problem with DP

Approach 1 (Greene)

  • We have a sub-problem \(P_{ik}\), bounded by the diagonal \(d_{ik}\). Here \(P_{06}\), bounded by \(d_{06}\).
  • Goal: compute \(w_{ik}\) = the minimum number of diagonals needed to decompose \(P_{ik}\) into convex regions.
  1. Build a convex polygon C inside \(P_{ik}\) that is adjacent to \(d_{ik}\) (it's of its sides).
  2. To close C, we need internal diagonals inside \(P_{ik}\) that are the other sides of C.
  3. These diagonals separate C from the rest of \(P_{ik}\).
  4. The regions left outside of C, each cut off by one of these diagonals, are now sub-problems.
  1. The weight of \(P_{ik}\) using this C is given by the formula below.

\(w_{ik} = \#\text{diagonals created} + \sum w(\text{sub-problems})\)

  • First, count the new diagonals. Each side of C that is a new diagonal in \(P_{ik}\) cuts off one sub-problem, so this number equals the number of sub-problems.
  • Then, add the weight of each sub-problem: the diagonals still needed inside it.
  • C itself costs 0, because it is already convex.
  1. The weight of \(P_{ik}\) is the minimum over all possible C next to \(d_{ik}\), so we would need to test all of them (hard). In our example the two choices give 2 and 1, and indeed \(w_{06}=1\).
Problem

Why we reject it:

  • We must test every possible convex polygon C next to \(d_{ik}\): too slow.
  • C splits \(P_{ik}\) into a variable, unpredictable number of sub-problems (1, 2, 3, 4, 5…): hard to code.

Approach 2 (Keil)

  • Pick a vertex \(p_j\) with \(i<j<k\) and draw the triangle \(T=(p_i,p_j,p_k)\) inside \(P_{ik}\). Here \(P_{08}\), with \(j=6\).
  • This creates at most 2 sub-problems:
    • left: \(P_{ij}\), bounded by \(d_{ij}\) (just a polygon edge if \(j=i+1\))
    • right: \(P_{jk}\), bounded by \(d_{jk}\) (just a polygon edge if \(j=k-1\))
  1. We solve both sub-problems first (bottom-up DP): \(w_{ij}\) and \(w_{jk}\) are already known.
  2. Then we decide if each of the two diagonals of T (\(d_{ij}\) and \(d_{jk}\)) is really needed. We can delete one, and merge its sub-problem with T, only if this creates no reflex vertex.

Example: can we delete the diagonals of T = p₀p₆p₈?

  • Suppose the solution chosen for \(P_{06}\) is just \(d_{04}\). The convex piece touching \(d_{06}\) is then \(Q=p_0p_4p_5p_6\).
  • To test a deletion, add the angles of the two pieces at each endpoint of the diagonal. If one sum is above \(180^\circ\), a reflex vertex appears and the diagonal must stay.

\(w_{ik} = \min_{i<j<k}\big(\,w_{ij} + w_{jk} + \text{extra}\,\big)\), with extra \(\in\{0,1,2\}\)

  • As in Approach 1, we test every valid \(p_j\) and keep the best triangle.
  • extra = number of diagonals of T that must be kept.
Better

What is better than Approach 1:

  • At most 2 sub-problems, always \(P_{ij}\) and \(P_{jk}\): a predictable pattern, easy to code.
  • A small set of choices: we only try each vertex \(p_j\), not every possible convex polygon C.
  • A simple cost: the triangle adds only 0, 1 or 2 diagonals.
Problem

Why this is still slow:

  • To know if \(d_{ij}\) or \(d_{jk}\) can be deleted, we need the angles of the convex piece touching it inside \(P_{ij}\) or \(P_{jk}\).
  • The weight \(w_{ij}\) only says how many diagonals, not where they are.
  • There can be exponentially many optimal decompositions of the same sub-polygon, so we cannot store them all.

Narrowest pairs: what we store instead

  • For each sub-polygon \(P_{xy}\) we store its weight \(w_{xy}\), plus a short list describing the angles at its base \(d_{xy}\).
  • For one decomposition, only the convex piece touching \(d_{xy}\) matters for later merges. We summarize its two angles at the base with a pair \([a;b]\): \(p_a\) is the neighbour of \(p_x\) on that piece, \(p_b\) the neighbour of \(p_y\).
  • We only store pairs coming from optimal decompositions (weight \(w_{xy}\)).
  • Example: \(P_{06}\) has two optimal decompositions, both with weight 1.

Why keep only the narrowest pairs?

  • A merge is allowed only if the angles add up to at most \(180^\circ\). So smaller angles are safer.
  • If one pair is nested inside another, its piece is narrower: smaller angles at both ends.
  • So whenever the wide piece can merge, the narrow one can too. The wide pair is useless and we delete it.

For each sub-polygon we store: its weight and the list of its narrowest pairs.

Keil's bottleneck: merging both sides at once

  • In Keil's triangle, both \(d_{ij}\) and \(d_{jk}\) can be deleted at the same time (extra = 0).
  • Then, at \(p_j\), three angles add up: the left piece, the triangle, and the right piece. The total must stay at most \(180^\circ\).
  • \(\alpha\) depends on the chosen pair of \(P_{ij}\), and \(\beta\) on the chosen pair of \(P_{jk}\). The condition links one choice on each side while \(p_i\) and \(p_k\) also constrain their outer ends.
  • A simple stack pop is no longer enough: because both sides can merge simultaneously, we must search the ordered lists of \(P_{ij}\) and \(P_{jk}\) for the best valid pairs.
  • Searching an ordered list takes a binary search, which costs an extra factor \(\log r\). This gives Keil's time \(O(nr^2\log r)\) instead of \(O(nr^2)\).

The paper's idea: never allow the double merge. Then only one side is tested, with a simple stack, and the \(\log r\) disappears.

Approach 3 (Keil & Snoeyink): Canonical Triangulations

To eliminate Keil's double-merge bottleneck, we restrict our search to a unique, standardized way of slicing any convex decomposition into triangles—called a canonical triangulation.

Core Idea: Every true minimum decomposition sits inside a canonical triangulation—and its strict fan rule locks one side of every triangle.

1. How to build a canonical triangulation (the fan rule)

  • Suppose we take any optimal decomposition of \(P\) into convex pieces.
  • Every convex piece has at least one vertex that was reflex in \(P\) (because convex pieces appear by breaking reflex vertices using diagonals).
  • This is how we triangulate each convex piece:
    1. Find the vertex in the piece with the lowest index that was reflex in \(P\), and connect it to all higher-index vertices in that piece.
    2. If the piece is still not completely triangulated, its highest-index vertex must also have been reflex in \(P\) \(\implies\) connect it to all remaining vertices in that piece.

2. Observation 2: One side of every triangle is locked

  • Any triangle \(\Delta(p_i, p_j, p_k)\) placed on \(d_{ik}\) belongs to the convex piece \(C\) touching \(d_{ik}\).
  • Because \(C\) obeys the canonical fan rule, one inner edge of the triangle can never be a dashed fan line—it is locked as a real cut (or outer border):
    • Case A (\(p_i\) reflex): Fan lines never connect \(p_j\) to \(p_k\) \(\implies\) \(d_{jk}\) is locked (border or real cut). We only test merging across \(d_{ij}\).
    • Case B (\(p_i\) convex \(\implies p_k\) reflex): Fan lines never connect \(p_i\) to \(p_j\) \(\implies\) \(d_{ij}\) is locked (border or real cut). We only test merging across \(d_{jk}\).
One side is always locked \(\implies\) the double-merge (extra = 0) never happens!
We only ever test one side using a simple stack in \(O(1)\) amortized time.
Deep dive: Why is one side guaranteed to be locked? (Proof sketch)

Case A (\(p_i\) reflex): Suppose \(j \neq k-1\) so \(d_{jk}\) is an internal diagonal, and assume for contradiction that \(d_{jk}\) is a dashed fan line inside some convex piece \(C\). Then \(p_i, p_j, p_k\) all belong to \(C\). By the canonical fan rule, every dashed line in \(C\) must connect either the lowest-index reflex vertex to higher indices, or the highest-index reflex vertex to indices. Since \(i < j < k\), neither \(p_j\) nor \(p_k\) can be the fan anchor, so \(d_{jk}\) cannot be a fan line—it must be a real cut of the decomposition.

Case B (\(p_i\) convex): Every sub-problem diagonal \(d_{ik}\) touches at least one reflex vertex (Claim 1), so \(p_k\) must be reflex. Since \(p_i\) is convex and \(i < j < k\), neither \(p_i\) nor \(p_j\) can be the fan anchor in \(C\), forcing \(d_{ij}\) (when \(j \neq i+1\)) to be a real decomposition cut.

Putting It All Together: Solving \(P_{ik}\) Bottom-Up

Now we combine everything into one bottom-up dynamic programming algorithm that solves small sub-polygons first (3 vertices, 4 vertices, …) up to the full polygon \(P_{0,n-1}\).

Goal for each \(P_{ik}\): Find the minimum diagonal count \(w_{ik}\) and save its surviving narrowest pairs \([a; b]\).

1. What we already know (Bottom-Up Assumption)

  • Because we solve sub-problems in order of increasing size, every smaller sub-polygon \(P_{xy}\) inside \(P_{ik}\) is already solved:
    1. We know its minimum diagonal count \(w_{xy}\).
    2. We have its list of narrowest pairs \([a; b]\) stored on a stack (ready to check in \(O(1)\) amortized time).

2. Solving \(P_{ik}\) (shown for Case A: \(p_i\) is reflex)

  1. Pick a triangle \(\Delta(p_i, p_j, p_k)\)
    Loop over valid intermediate vertices \(j\) (\(i < j < k\)).
    This splits \(P_{ik}\) into two already-solved pieces: \(P_{ij}\) (left) and \(P_{jk}\) (right).
  2. Lock the right edge \(d_{jk}\)
    By Observation 2, \(d_{jk}\) is always kept \(\implies\) adds a mandatory +1 cost.
  3. Test merging the left edge \(d_{ij}\)
    Check the saved narrowest pairs \([s; t]\) of \(P_{ij}\) to see if erasing \(d_{ij}\) keeps both corners \(p_j\) and \(p_i\) convex (\(\le 180^\circ\)):
    Merge succeeds: Erase \(d_{ij}\) (\(+0\)) \(\implies\) total cost is \(w_{ij} + w_{jk} + 1\), new pair to save is \([s; j]\).
    Merge fails: Keep \(d_{ij}\) (\(+1\)) \(\implies\) total cost is \(w_{ij} + w_{jk} + 2\), new pair to save is \([j; j]\).

\[w_{ik} = \min_{\substack{i < j < k \\ d_{ij}, d_{jk} \text{ exist}}} \begin{cases} w_{ij} + w_{jk} + 2 & \text{if } d_{ij} \text{ must be kept} \\ w_{ij} + w_{jk} + 1 & \text{if } d_{ij} \text{ can be erased (merged)} \end{cases}\]

Repeat symmetrically if Case B (\(p_i\) convex \(\implies p_k\) reflex)
Deep dive: Why border edges cost 0 in the formula (the \(-1\) convention)

In the recurrence above, we always add \(+1\) for the locked edge \(d_{jk}\). What if \(j = k - 1\), so \(d_{jk}\) is just an exterior polygon border (which should cost \(0\) cuts)?

By initialization convention, every exterior polygon edge \(P_{x(x+1)}\) is given weight \(w_{x(x+1)} = -1\). When \(j = k - 1\), the formula computes \(w_{ij} + (-1) + 1 = w_{ij} + 0\)—automatically canceling out the \(+1\) so borders are free!

Deep dive: Which vertices \(j\) does the loop actually test?

We do not test every index between \(i\) and \(k\). For a candidate \(j\) to be valid in Case A (\(p_i\) reflex):

  • Visibility: Both \(d_{ij}\) and \(d_{jk}\) must stay completely inside \(P\).
  • Reflex requirement: Because \(d_{jk}\) is locked as a real cut (unless \(j = k - 1\)) and every real cut must touch at least one reflex vertex (Claim 1), we only test \(j = k - 1\) or vertices \(j\) where at least one of \(p_j\) or \(p_k\) is reflex.
Deep dive: How the two-corner angle check & stack scan work

When erasing \(d_{ij}\) to glue a narrowest pair \([s; t]\) of \(P_{ij}\) (with corners \(s \to i \to j \to t\)) onto \(\Delta(p_i, p_j, p_k)\), two corners must stay non-reflex (\(\le 180^\circ\)):

  • Corner 1 (\(p_j\)): Edge \(d_{tj}\) meets \(d_{jk}\). We pop \(P_{ij}\)'s stack to skip pairs where \(\angle(d_{tj}, d_{jk}) > 180^\circ\), stopping at the last valid pair \([s; t]\).
  • Corner 2 (\(p_i\)): Edge \(d_{is}\) meets \(d_{ik}\). We verify \(\angle(d_{is}, d_{ik}) \le 180^\circ\). If both pass, the merge succeeds with pair \([s; j]\); otherwise we keep \(d_{ij}\) with pair \([j; j]\).

Stack orientation note: Each sub-problem's sorted list of narrowest pairs is stored as a double-ended list: \(S_{xy}\) (increasing order, largest on top) and \(T_{xy}\) (decreasing order, smallest on top). Case A pops \(T_{ij}\) (scanning in CCW order), while Case B pops \(S_{jk}\) (scanning in CW order). Popped pairs are permanently invalid for larger sub-problems and discarded forever.

Deep dive: Complete Algorithm

For readers interested in the exact implementation details, here is the bottom-up control flow and the two worker subroutines:

Procedure MCD(P):
  Initialize weights of edges w[i][i+1] = -1;
  for visible(i, i + 2) { w[i][i+2] = 0; push [i+1, i+1] on S[i][i+2]; }
  for size = 3 to n do {
    // Pass 1: pi is reflex (TypeA)
    for reflex pi with i + size <= n do {
      k = i + size;
      if visible(i, k) {
        if (pk reflex) for j = i + 1 to k - 1 do TypeA(i, j, k);
        else {
          for reflex pj with i < j < k - 1 do TypeA(i, j, k);
          TypeA(i, k - 1, k);
        }
      }
    }
    // Pass 2: pi is convex, pk is reflex (TypeB)
    for reflex pk with size <= k < n do {
      i = k - size;
      if (pi not reflex and visible(i, k)) {
        TypeB(i, i + 1, k);
        for reflex pj with i + 1 < j < k do TypeB(i, j, k);
      }
    }
    Mirror S[i][k] into T[i][k];
  }
