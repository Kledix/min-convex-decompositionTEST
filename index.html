Minimum Convex Decomposition

How do we cut a simple polygon into the fewest possible convex pieces?

Based on the algorithm by J. Mark Keil & Jack Snoeyink (2002)

Project by Deliallisi Klejdi

Try the demo ↓

Abstract

Many algorithms (collision detection, path planning, rendering) work far better on convex shapes than on arbitrary ones. We study the problem of splitting a simple polygon into the fewest convex pieces using non-crossing diagonals. We start from the brute-force solution, whose cost explodes with the polygon size, then follow the dynamic-programming line of work of Greene (1983), Keil (1985) and Keil & Snoeyink (2002), explaining what each step fixed. An interactive demo lets you build a polygon and watch a fast heuristic decompose it, compared with a provable lower bound.

1. Introduction

A simple polygon is a closed chain of \(n\) straight edges that never crosses itself. It is convex if the segment joining any two of its points stays inside. A vertex is reflex when its interior angle exceeds 180°; a polygon is convex exactly when it has no reflex vertex. We write \(r\) for their number.

A diagonal joins two vertices through the interior. A triangulation adds diagonals until only triangles remain, and always uses exactly \(n-2\) triangles. A convex decomposition only asks for convex pieces, so it can use far fewer.

Lower bound. A diagonal can fix at most two reflex vertices (one at each end), so any decomposition needs at least \(\lceil r/2\rceil+1\) pieces. For the L-shape, \(r=1\) gives 2, so the result above is optimal.

Why only simple polygons?

This project is restricted to simple polygons, because for a polygon whose edges cross each other the basic notions we rely on are no longer well defined:

  • Interior: the inside of the polygon is ambiguous. Different conventions (even-odd rule, winding number) can give different regions, so "a diagonal lying inside" has no single meaning.
  • Diagonals: a segment may cross an edge or pass through a crossing point that is not a vertex, so it is unclear which segments are valid diagonals.
  • Visibility: two points "seeing each other" relies on the segment staying inside the polygon, which again depends on the chosen interior.
  • Structure: a diagonal no longer splits the polygon into exactly two sub-polygons, and results such as "a triangulation has \(n-2\) triangles" no longer hold. The dynamic programming below relies on this splitting.

Simple polygons give a clean, unambiguous setting, which is why the literature on this problem uses them.

2. The Problem: The Robot Vacuum Analogy

Imagine a robot vacuum in an L-shaped flat. To plan its route, it would like every zone to have no hidden corners. A region where any two points can see each other (the segment between them stays inside) is called convex.

Formally: given a simple polygon, partition it into the minimum number of convex sub-polygons using non-crossing diagonals (Steiner points are not allowed in this version of the problem). A Steiner point is an extra vertex that is not a vertex of the original polygon, for example a point on an edge where a cut ends. Here every cut must join two existing vertices.

Note on Steiner points: If we allow segments to end at arbitrary new points (Steiner points) rather than just existing vertices, the problem was solved in \(O(n + r^3)\) time by Chazelle and Dobkin (1985). This project focuses strictly on decompositions without Steiner points, where cuts must join existing vertices.

3. A Naive Approach (and Why It Fails)

Brute force: try every set of diagonals

1. D ← all valid diagonals of P                 # O(n²) candidates, O(n) test each
2. for every subset S of D with no two diagonals crossing:
3.     pieces ← cut P along S
4.     if every piece is convex: keep S if |S| + 1 is the smallest so far
5. return the best S

It works: it examines every possible answer, so the result is exactly optimal. It does not scale: a polygon has up to \(D=n(n-3)/2\) diagonals, hence up to \(2^{D}\) subsets. Keeping only non-crossing subsets helps but the count stays exponential (about \(5.83^n\) for polygons whose vertices see each other).

Where does 5.83 come from?

Count the sets of non-crossing diagonals of a convex \(n\)-gon (the most favourable case for diagonals): 1, 3, 11, 45, 197, 903 for \(n=3,\dots,8\) (the little Schröder numbers). The ratio between consecutive terms tends to \(3+2\sqrt2\approx5.83\), so the count grows like \(5.83^n\). For comparison, complete triangulations alone only grow like \(4^n\). A simple polygon has fewer valid diagonals, so this is an upper bound.

Greedy: triangulate, then merge

1. T ← any triangulation of P                  # e.g. ear clipping
2. for each diagonal d of T:
3.     if removing d keeps the merged piece convex: remove d
4. return the remaining pieces

This is the Hertel–Mehlhorn heuristic used in the demo. It is fast (linear after the triangulation) and always valid, but not optimal: the order of the merges can lock in a bad choice.

Why it is within a factor 4 of the optimum

Every diagonal left at the end is essential: removing it would create a reflex angle at one of its endpoints. A reflex vertex can have at most two essential diagonals incident to it (a third would be removable). So at most \(2r\) diagonals remain, giving at most \(2r+1\) pieces. Since \(\mathrm{OPT}\ge\lceil r/2\rceil+1\), the ratio is below 4.

So: brute force is exact but exponential, greedy is fast but only approximate. The dynamic-programming algorithms below are exact and polynomial.

4. Algorithmic Evolution

All three algorithms below are exact dynamic programs over sub-polygons cut off by a diagonal. They differ in how many subproblems they create and how much each one costs. Here \(n\) is the number of vertices and \(r\) the number of reflex vertices.

1983

Greene — \(O(n^2 r^2)\)

Idea. For a diagonal \(d\), some convex piece of the optimal solution is incident to \(d\). Greene builds this piece vertex by vertex, removes it, and solves what remains.

Limit. Removing a piece with \(k\) sides can leave up to \(k-1\) separate sub-polygons: one problem becomes many, and every combination of piece shapes must be examined.

Proof sketch of the bound

A subproblem is a diagonal with a reflex endpoint, so there are \(O(rn)\) of them. Choosing the convex piece next to a diagonal means exploring \(O(rn)\) candidate extensions. Multiplying gives \(O(rn)\cdot O(rn)=O(n^2r^2)\).

1985

Keil — \(O(nr^2\log r)\)

What is new. Keil shows that not all extensions need testing. Among the candidate diagonals, only the narrowest pairs (the most closely bounding ones) can appear in an optimal solution, so the others are discarded.

Gain. The number of subproblems stays \(O(rn)\), but the work per subproblem drops from about \(rn\) to \(r\log r\).

Proof sketch of the bound

Replacing the \(O(rn)\) work per subproblem by \(O(r\log r)\) gives \(O(rn)\cdot O(r\log r)=O(nr^2\log r)\). Correctness rests on the definition of narrowest pairs: the convex region of such a pair, near the diagonal, does not contain the convex region of any other minimum decomposition, so discarding the other candidates loses nothing.

2002

Keil & Snoeyink — \(O(n + r^2\min(r^2,n))\)

What is new. Instead of removing whole convex pieces, the recurrence works on a canonical triangulation and removes a single triangle per step. A triangle leaves at most two subproblems, so the fan-out of Greene disappears.

Gain. Restricting to biased convex decompositions leaves at most \(\min(n,r^2)\) useful convex endpoints, so the number of subproblems drops from \(O(rn)\) to about \(O(r\min(r^2,n))\), each solved in \(O(r)\) time. When \(r\) is small relative to \(n\), this is dramatically faster, and it never exceeds \(O(n^3)\).

Proof sketch of the bound

States: \(O(r\min(r^2,n))\). Work per state: \(O(r)\). Product: \(O(r^2\min(r^2,n))\), plus \(O(n)\) for preprocessing. Since \(r\le n\), the total is at most \(O(n^3)\).

How the bounds are derived

For a dynamic program, running time = number of states × work per state. Here a state is a diagonal, i.e. a sub-polygon to solve. Reading the three algorithms this way shows where each gain comes from.

  • Greene. A useful diagonal has at least one reflex endpoint (\(r\) choices) and any other endpoint (\(n\) choices): \(O(rn)\) states. Building the convex piece incident to a diagonal costs about \(O(rn)\) again. Total: \(O(rn)\cdot O(rn)=O(n^2r^2)\).
  • Keil. Same \(O(rn)\) states, but the narrowest pairs discard most candidates, so each state costs only \(O(r\log r)\). Total: \(O(rn)\cdot O(r\log r)=O(nr^2\log r)\).
  • Keil & Snoeyink. To prove the complexity, the 2002 paper (Theorem 3) does not use the "states × work" logic. Instead, it demonstrates that the algorithm globally makes at most \(O(r^2\min(r^2,n))\) calls to its subroutines (thanks to the initial ray-shooting reduction). During these calls, the computation time is a constant plus the number of elements popped from the stacks. Since elements are pushed at most once, the total number of pops over the entire execution cannot exceed \(O(r^2\min(r^2,n))\). Therefore, the total running time is strictly bounded by \(O(n + r^2\min(r^2,n))\).

Sanity check. If \(r\) grows like \(n\), Greene gives \(n^4\) while Keil & Snoeyink give \(n^2\cdot n=n^3\). If \(r\) is a constant, Keil & Snoeyink reduce to \(O(n)\).

What comes from the paper. The 2002 article states the total bounds and the \(\min(n,r^2)\) relevant endpoints. The split into states and work per state is a structural reading of those totals, not something the paper spells out for Greene and Keil.

Why the 2002 paper is a real breakthrough

  • It changes the structure of the recurrence. Earlier algorithms only tuned the cost of each step; Keil & Snoeyink removed the root cause, the fan-out of one problem into many.
  • It improves the worst case. From \(O(n^4)\) (Greene) to \(O(n^3)\), and it removes the \(\log r\) factor of Keil, since \(\min(r^2,n)\le n\).
  • It adapts to the input. The cost depends on \(r\), not only on \(n\): for a convex polygon (\(r=0\)) or any constant \(r\), the running time is linear, \(O(n)\).

What does "one triangle per step" mean?

Greene removes a whole convex piece with \(k\) sides, and every side except the base opens its own independent sub-polygon: the problem explodes into many at once. Keil & Snoeyink fix a canonical triangulation (a triangulation chosen by a fixed rule) so that, for each sub-polygon, the triangle sitting on its base diagonal is predictable. Removing only that triangle leaves at most two sub-polygons.

Concretely, for a sub-polygon bounded by the diagonal \((v_i,v_j)\), the triangle \(\Delta(v_i,v_j,v_k)\) cuts it into \(P_{i,k}\) and \(P_{k,j}\), whose answers were computed earlier.

Why only diagonals with a reflex endpoint matter

Cutting is only useful to remove a reflex angle. A diagonal whose two endpoints are both convex can always be erased: the two pieces it separates merge without creating any reflex angle, because at each endpoint the merged angle equals the original interior angle, which is below 180°. A minimum decomposition therefore never needs such a diagonal. This reduces the candidates from \(O(n^2)\) to \(O(rn)\).

Proof sketch

Let \(d\) join two convex vertices \(u,w\) of the polygon. The angles of the two adjacent pieces at \(u\) add up to the polygon's interior angle at \(u\), which is below 180°; the same holds at \(w\). All other vertices keep their angles. So the union of the two pieces is convex, and removing \(d\) gives a valid decomposition with one piece fewer.

This is a necessary ingredient, but it was already used by Greene and Keil. The new ideas of 2002 are the biased convex decompositions, which shrink the set of useful endpoints, and the canonical triangulation, which limits each step to two subproblems.

From \(n\) to \(\min(n, r^2)\) relevant endpoints

Count the candidate states. A diagonal needs at least one reflex endpoint, and the other endpoint can be any vertex: \(r\times n\) pairs, hence \(O(rn)\) states for Greene and Keil. Keil & Snoeyink restrict the problem to biased convex decompositions. They prove that we only need to consider diagonals ending at specific convex vertices (found by extending lines from reflex vertices). By using a ray-shooting preprocessing step, they eliminate useless convex vertices, reducing the number of valid endpoints to at most \(\min(n, r^2)\). This geometric reduction, combined with the DP, yields the final bound.

Why a canonical triangulation?

If the geometric reduction above bounds the number of states, the canonical triangulation bounds the fan-out (the number of new subproblems created). A canonical triangulation is built with a fixed rule (e.g., connecting the lowest-indexed reflex vertex to others in the piece), so every sub-polygon has exactly one predictable triangle on its base diagonal. The recurrence is then unambiguous, and removing this single triangle creates at most two smaller subproblems instead of splitting into many parts like Greene did.

Why reflex vertices are so important

  • Convexity: a polygon is convex exactly when it has no reflex vertex, so reflex vertices are the only obstacle.
  • Cuts: a cut matters only if it touches a reflex vertex (shown above).
  • Lower bound: each diagonal fixes at most two of them, so at least \(\lceil r/2\rceil+1\) pieces are needed.
  • Complexity: \(r\) measures how hard the polygon really is, which is why it appears in every bound.

Why \(r\) is an interesting parameter

Many real polygons, such as floor plans, building footprints or parcels, have many vertices but few notches: a large \(n\) with a small \(r\). The cost \(O(n+r^2\min(r^2,n))\) then stays close to linear. This is not universal: a finely sampled curved boundary can have \(r\) proportional to \(n\), and the bound degrades to \(O(n^3)\).

6. Under the Hood: Mathematics

Trying every set of diagonals takes exponential time. Dynamic programming avoids this thanks to optimal substructure: an optimal decomposition of a polygon contains optimal decompositions of its sub-polygons.

The Keil & Snoeyink algorithm, step by step

A simplified outline of the algorithm, to see how the pieces fit together:

  1. Step 1: Preprocess. Identify the \(r\) reflex vertices. Use ray shooting to find the limited set of convex vertices that can actually form valid optimal diagonals (RE-diagonals and DE-diagonals).
  2. Step 2: List the candidate diagonals. Compute which pairs of these relevant vertices see each other inside the polygon. Thanks to the preprocessing, there are at most \(O(\min(n, r^2))\) valid convex endpoints, drastically reducing the state space.
  3. Step 3: Define the subproblems. Each candidate diagonal cuts off a sub-polygon. Its answer is the minimum number of convex pieces needed to decompose it, along with a stack of the "narrowest" geometric shapes achieving this minimum.
  4. Step 4: Handle the base case. The weight (piece count) of each polygon edge is initialized to \(-1\) by convention.
  5. Step 5: Apply the recurrence. For each sub-polygon, try the possible canonical triangles next to its diagonal. Each choice leaves at most two smaller sub-polygons. Instead of explicitly calculating a merge penalty, the algorithm pops solutions from the stored stacks in angular order to find the narrowest piece that does not create a reflex angle.
  6. Step 6: Fill the table bottom-up. Process the sub-polygons from the smallest to the largest, so every answer is computed once and reused.
  7. Step 7: Reconstruct the solution. Starting from the whole polygon, follow the stored best choices back down to form the minimum convex decomposition.

Subproblems

Let \(P=(v_0,\dots,v_{n-1})\). For a diagonal \((v_i,v_j)\), let \(P_{i,j}\) be the sub-polygon it cuts off, and \(\mathrm{OPT}(i,j)\) the minimum number of convex pieces for it.

Recurrence (sketch)

Fix the canonical triangle \(\Delta(v_i,v_j,v_k)\) incident to the diagonal. It leaves at most two smaller subproblems, \(P_{i,k}\) and \(P_{k,j}\). Taking the best \(k\) and accounting for whether the triangle merges with a neighbouring piece gives $$\mathrm{OPT}(i,j)=\min_{k}\big(\mathrm{OPT}(i,k)+\mathrm{OPT}(k,j)-\text{merge}(i,j,k)\big).$$ Since every valid choice of \(k\) is tested, the minimum over all of them is the optimum. This formula is a didactic simplification. The actual algorithm has no subtractive merge term: it handles merging dynamically, adjusting the count (+1 or +2) according to whether the merge creates a reflex angle, using stacks of narrowest pairs.

The merge problem

Adding \(\mathrm{OPT}(i,k)+\mathrm{OPT}(k,j)+1\) for the triangle overcounts if the triangle and the adjacent pieces can fuse into one convex piece. Whether they can depends on the angles: if the merged angle at the diagonal's endpoint is less than 180°, the merge is legal. To handle this efficiently, the DP does not just store the optimal count. It maintains a stack of narrowest pairs (the tightest possible convex bounds of the sub-solution) sorted by angle. By popping from these stacks, the algorithm finds the best valid merge without exploring all geometric combinations.

Complexity

  • States: a subproblem is a diagonal, and there are at most \(\binom{n}{2}=O(n^2)\) of them.
  • Transition: choosing \(v_k\) costs \(O(n)\) candidates per state.
  • Total: \(O(n^2)\times O(n)=O(n^3)\).

The refinement. Only diagonals with at least one reflex endpoint matter (proof in Section 4). This cuts the candidates from \(O(n^2)\) to \(O(rn)\); the biased convex decompositions of Keil & Snoeyink then reduce the useful other endpoints to at most \(\min(n,r^2)\), which leads to the final bound \(O(n + r^2\min(r^2,n))\).

7. Beyond Simple Polygons: Polygons with Holes

Everything above assumes a polygon without holes. If the polygon may contain holes (think of a room with pillars), the problem changes nature: minimum convex decomposition becomes NP-hard (Lingas, 1982). No polynomial-time exact algorithm is expected unless P = NP.

The intuition: in a simple polygon, each diagonal splits the problem into two independent parts, which is exactly what dynamic programming needs. With holes, a diagonal may not disconnect the polygon, so the subproblems are no longer independent. In practice one uses approximations such as the Hertel–Mehlhorn heuristic from Section 3, which still applies. This lies beyond the scope of this project.

8. Real-World Applications

🎮

Physics engines

Collision tests between convex shapes are cheap and robust (GJK, SAT). Concave bodies are split into convex parts first.

🤖

Robotics

Free space split into convex regions: any two points in a region are connected by a straight, safe path.

👁️

Shape analysis

Convex parts act as simple building blocks for recognising and comparing shapes.

9. Conclusion

Minimum convex decomposition is a good example of how a few basic notions of computational geometry (convexity, reflex vertices, diagonals, triangulations) combine into a problem that is easy to state and surprisingly hard to solve well. A naive search is exact but unusable beyond a handful of vertices, a greedy heuristic is fast but only approximate, and the dynamic-programming algorithms of Greene, Keil and Keil & Snoeyink bring the exact answer into polynomial time, step after step. The problem remains relevant today, since convex pieces are the standard building blocks of physics engines, robot navigation and shape analysis. Yet finding the true optimum is not easy: the best exact algorithm is intricate, and as soon as the polygon has holes the problem becomes NP-hard, so in practice simple heuristics are often what actually gets used.
